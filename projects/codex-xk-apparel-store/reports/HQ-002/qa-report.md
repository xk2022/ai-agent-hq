## 2. 人類10秒驗收方法（尚未執行）

1. 在 GitHub 實際渲染的 README 頁面測量；記錄頁面版本、時間、桌面／手機 viewport。載入完成後開始計時。
2. 至少1名實際目標管理者（包含owner）參與；事前只說明六個問題，不提供答案或導覽訓練。多人測試可加強證據，但不是本任務新增的硬門檻。
3. 開啟首頁後，參與者於10秒內指出六問答案位置並簡短確認：有哪些專案、有問題的專案、最高風險、最近成果、下一步、待批准事項。不得進完整技術報告找答案。
4. 每位參與者六問全對、沒有將建議認成授權、沒有把歷史測試或部署當成即時站況才通過；紀錄秒數、答案、錯誤與介面版本。
5. Markdown結構代理演練只能驗證資訊位置及語意，不替代管理者實際理解速度、手機呈現或真實可及性驗收。
